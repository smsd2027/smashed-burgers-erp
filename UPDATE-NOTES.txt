Smashed Burgers ERP – Sales & Login Update

Changes:
- Monthly sales imports now support two explicit modes:
  1) Replace monthly report: removes all existing sales entries for the selected branch/channel and month (including legacy daily rows), then saves the new report as one monthly record.
  2) Add to existing report: combines the imported quantities with the existing monthly totals and saves one consolidated monthly record.
- Admin can select historical months and edit saved item quantities and unit prices; totals and reports recalculate.
- Admin can also rename menu items in the Menu tab; historical sales continue to follow the same item record.
- Account picker now uses circular profile-style avatars, with a crown-themed Admin avatar, chef-themed Cashier avatar, and the existing Smashed Burgers logo for the Smashed account. Access descriptions have been removed.
- Added the PWA icon image files required by the existing manifest and service worker, and incremented the service-worker cache version.

Not changed:
- Dashboard logic and presentation.
- Dispatch logic and presentation.
- Existing backend routes, Supabase schema, stored data, and environment-variable names.

Deployment:
- Replace the existing project files with the files in this ZIP through your normal GitHub/Render deployment workflow.
- Do not rerun the Supabase setup SQL for this update.
- Keep your existing Render environment variables and Supabase database.
- Back up your Supabase data before deploying, as with any ERP update.

Checks performed:

Smashed Burgers ERP – P&L & Foodpanda Settlement Update (2026-11-26)

Changes:
- Added a dedicated monthly Foodpanda settlements panel to the Dashboard/P&L. Admin enters the actual net payout received for each Foodpanda channel and month, then saves all branch payouts together.
- The P&L calculates the difference between recorded Foodpanda sales and the entered payout as effective platform deductions, and calculates the effective deduction percentage beside the Foodpanda branch/channel name.
- Removed the standalone commission-percentage column to keep the P&L easier to scan.
- Fixed Gulshan and Dhanmondi rent and bills allocation: 100% is charged to the corresponding Dine In channel and 0% to Foodpanda.
- Foodpanda channels with a missing payout remain visibly pending. Their known food and other costs are still included in total expenses; the overall profit is labelled provisional until all payouts are entered.
- Improved validation so payout entries cannot be negative or non-numeric. Blank means the payout has not been received/entered yet; zero is a valid saved payout.
- Restyled the account picker to use the Smashed Burgers charcoal-and-yellow brand palette instead of the brown/orange override.
- Bumped the service-worker cache to v17 so clients fetch the updated application shell.

Payout entry workflow:
1. Open Dashboard.
2. Select the month in the month selector.
3. In “Foodpanda monthly settlements”, enter the net payout actually received for each Foodpanda branch for that month.
4. Select “Save monthly payouts”.
5. Review the P&L below. Effective deductions and percentages calculate automatically.

Financial treatment:
- Dine In paycheck/revenue equals its recorded net sales.
- Foodpanda paycheck/revenue equals the actual payout entered in the settlement panel.
- Effective Foodpanda deductions = recorded Foodpanda sales minus actual payout. This may include platform commission and other settlement adjustments, so it should not be interpreted as commission alone if the platform statement contains other deductions.
- Gulshan and Dhanmondi rent/bills and salary are assigned entirely to Dine In.
- Wastage remains displayed separately and is not included in operating profit, consistent with the existing P&L treatment.

Deployment:
- Back up the live ERP before deployment.
- Replace the project files using the existing GitHub/Render workflow.
- Keep existing Render environment variables and Supabase configuration. Do not rerun Supabase setup SQL.
- After deployment, refresh the ERP. If an older PWA shell remains cached, close/reopen the installed app or reload after the service worker updates.

Checks performed:
- Inline JavaScript syntax validation with Node.js.
- Python backend compilation.
- ZIP integrity check.
- Focused calculation test for Foodpanda payout reconciliation and Dine In-only Gulshan/Dhanmondi overhead allocation.

Not live-tested:
- No connection was made to the production Render service or Supabase database. Actual live data and browser workflow still need confirmation in the deployed environment.
- Fixed a historical-sales edge case: an explicit zero sales override is now respected instead of silently falling back to item-level sales. Admin can use “Use item sales” to clear the override and return to calculated totals.
